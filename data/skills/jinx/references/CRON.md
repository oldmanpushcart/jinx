# 定时任务管理

定时任务系统支持两类任务，由配置文件中的 `type` 字段（**必填**）区分：**周期任务**（`type=cron`，按 Cron 表达式重复触发）与**一次性任务**（`type=at`，在指定绝对时间触发一次后终结）。任务触发时向 Agent 发送指定 prompt 执行，结果回写到发起任务的会话。

## 任务类型选型（必读）

创建任务前必须先判断用户的诉求是"重复发生"还是"只发生一次"，选错类型会导致任务行为完全不符合预期：

| | 周期任务 `type=cron` | 一次性任务 `type=at` |
|---|---|---|
| 触发规律 | 按 Cron 表达式**无限重复**触发 | 在指定的绝对时间**只触发一次**，触发后终结、不再续期 |
| 适用诉求 | "每天早上 9 点提醒我"、"每隔 30 分钟检查一次"、"每周一汇总" | "明天上午 10 点提醒我一下"、"3 分钟后叫我"、"8 月 27 日 16:31 提醒开会" |
| 时间表达 | `cron` 字段（6 位表达式，**无年份字段**） | `at` 字段（ISO 本地时间，精确到具体某一刻） |
| 调度模式 | 支持 `mode`（delay/fixed） | 不支持 `mode`（触发一次即终结，无重叠问题） |
| 过期行为 | 按表达式继续调度下一个触发点 | 激活时触发时刻已过去，则**不补触发**、不挂调度 |

**硬性规则：**
1. 一次性诉求**必须**用 `type=at`，**禁止**用具体日期的 cron 表达式冒充一次性——cron 没有年份字段，`0 0 10 1 9 ?`（9 月 1 日 10:00）会**每年**重复触发；
2. 重复诉求**必须**用 `type=cron`，禁止为每次触发创建一个一次性任务；
3. 相对时间（如"3 分钟后"）需先换算成绝对时间再写入 `at`。

## 命令

```bash
sh ./bin/jinx.sh cron list                  # 列出所有定时任务（含 TYPE、SESSION 列）
sh ./bin/jinx.sh cron detail <NAME>         # 查看指定任务的详细信息
sh ./bin/jinx.sh cron reload <NAME>         # 重新加载指定任务
```

## 创建任务

由 Agent 通过文件编辑直接创建，步骤如下：

1. 取系统上下文运行时信息中的 `SESSION`（会话 ID），作为 `session_id` 字段值（任务触发后的执行结果将回写到该会话）；
   **若上下文中没有会话 ID，必须终止创建并告知用户失败原因，不得写入配置文件**；
2. 按上文选型确定 `type`，使用文件编辑工具写入配置文件 `{jinx.data}/cron/{name}.cron.json`，格式见下节；
3. 执行 `sh ./bin/jinx.sh cron reload <NAME>` 强制生效（不得依赖系统 10 秒自动扫描代替 reload）。

**文件编辑硬性要求：** 配置文件必须采用 **UTF-8** 编码；任何编辑完成后必须执行 `cron reload <NAME>` 强制生效。

## 配置文件

路径：`{jinx.data}/cron/{name}.cron.json`，文件名须与 JSON 中 `name` 字段严格一致。

### 周期任务模板（type = cron）

```json
{
  "type": "cron",
  "name": "health-check",
  "cron": "0 */30 * * * ?",
  "prompt": "检查系统健康状态，如有异常生成报告",
  "enabled": true,
  "mode": "delay",
  "session_id": "S4650279831"
}
```

### 一次性任务模板（type = at）

```json
{
  "type": "at",
  "name": "meeting-reminder",
  "at": "2026-08-27T16:31",
  "prompt": "提醒用户下午四点半的会议",
  "enabled": true,
  "session_id": "S4650279831"
}
```

`at` 为 ISO 本地时间（`yyyy-MM-ddTHH:mm`，按系统时区解释）。

### 字段说明

| 字段         | 说明 |
|--------------|---|
| `type`       | 任务类型（**必填**）：`cron`（周期）或 `at`（一次性）；缺失或值未知时配置解析失败，任务不会被加载 |
| `name`       | 任务名（英文，小写字母、数字和连字符），须与文件名一致 |
| `cron`       | 周期任务专用：Cron 表达式（**固定 6 位**：秒 分 时 日 月 周，格式规范见下节，写错会导致任务无法加载） |
| `at`         | 一次性任务专用：ISO 本地时间（如 `2026-08-27T16:31`），格式非法会导致任务无法加载 |
| `prompt`     | 触发时发送给 Agent 执行的指令 |
| `enabled`    | 启停控制，`false` 表示暂停 |
| `mode`       | 周期任务专用：调度模式（可选，缺省 `delay`），见下节；一次性任务不得配置此字段 |
| `session_id` | CHAT 会话 ID（**必填**）：任务触发时在该会话执行并回写结果。直接使用系统上下文运行时信息中的 `SESSION`；缺失时配置解析失败，任务不会被加载 |

## Cron 表达式格式规范（必读）

系统使用 Micronaut 的 `CronExpression` 解析，**只接受 5 位或 6 位**，jinx 统一使用 **6 位**（首位是秒）。**不支持年份字段**，写 7 位直接解析失败。

| 位置 | 字段 | 取值范围 | 允许的特殊字符 |
|---|---|---|---|
| 1 | 秒 | `0-59` | `*` `,` `-` `/` |
| 2 | 分 | `0-59` | `*` `,` `-` `/` |
| 3 | 时 | `0-23` | `*` `,` `-` `/` |
| 4 | 日 | `1-31` | `*` `,` `-` `/` `?` |
| 5 | 月 | `1-12`（或 `JAN-DEC`） | `*` `,` `-` `/` |
| 6 | 周 | `1-7`（或 `SUN-SAT`，1=SUN） | `*` `,` `-` `/` `?` |

**硬性约束：**
1. 每个字段的值必须在取值范围内：时最大 `23`、日最大 `31`、月最大 `12`、周最大 `7`。超范围（如小时写 `25`、日写 `32`）直接解析失败；
2. **日与周字段二选一**：其中一个必须是 `?`，不允许两个字段同时指定具体值；
3. 字段之间用**单个空格**分隔，不多不少；
4. 不支持 `L`、`W`、`#` 等高级符号，也不支持 `@daily` 等宏；
5. 写入前自查一遍：共 6 位？每位在合法范围内？日和周是否恰好一个 `?`？

错误示例：`0 16 25 8 ? *`（小时 `25` 超出 0-23 范围，解析失败）；`0 0 12 1 1 ? 2099`（7 位含年份，解析失败）。

### 表达式示例

| 表达式 | 含义 |
|---|---|
| `0 */30 * * * ?` | 每 30 分钟执行一次 |
| `0 30 10 * * ?` | 每天 10:30 执行 |
| `0 0 9 ? * MON` | 每周一 9:00 执行 |
| `0 0 10 1 9 ?` | 每年 9 月 1 日 10:00 执行（**每年重复**；若只需一次，改用 `type=at`） |
| `0 31 16 * * ?` | 每天 16:31 执行 |

**高频踩坑警示（真实事故）：** 最常见的错误是把时、分的值写进秒、分的位置——这类错误**语法合法、能正常加载，但触发时间完全不对**，比语法错误更隐蔽。
例如"每天 16:31 执行"：
- 正确：`0 31 16 * * ?`（秒 0、分 31、时 16）；
- 错误：`31 16 * * * ?`（秒 31、分 16、时 \*）→ 实际变成**每小时的 16 分 31 秒**执行。

写完表达式后，逐字段对照位置表默读一遍："秒=? 分=? 时=?"，确认与用户要求的时刻一致再写入。

## 调度模式（mode，仅周期任务）

| 模式 | 语义 | 重叠行为 |
|---|---|---|
| `delay` | 固定延迟（默认）：上次执行**完成后**，再调度完成时刻之后的下一个 cron 触发点；错过的一次性触发点不补跑 | 天然串行，不重叠 |
| `fixed` | 固定频率：严格按 cron 时刻触发，不等待上次执行完成 | 上次未完成时允许并行执行 |

选择建议：短促任务且必须准点用 `fixed`；执行时间较长、同一任务并发会互相干扰的用 `delay`。一次性任务触发一次即终结，无重叠问题，不得配置此字段。

## 其他操作

- **删除任务**：删除对应的配置文件，系统自动检测移除；如需改名，等同删除旧配置 + 创建新配置。
- **暂停/恢复任务**：修改配置文件中 `enabled` 字段（`false` 为暂停，`true` 为恢复），随后执行 `cron reload <NAME>` 强制生效。

## 执行记录

任务在 `session_id` 指定的会话中执行（即哪个会话发起的任务，结果回写到哪个会话），执行历史可通过该会话查询。
